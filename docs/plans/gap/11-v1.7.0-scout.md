# Scout Report — better-auth v1.6.25 → v1.7.0-rc.2 Gap Analysis

**Scope note on the commit count:** the dispatch mandate said "81 non-merge commits." The actual range `v1.6.25..v1.7.0-rc.2` contains **212 total commits: 169 non-merge + 43 merges** (verified via `gh api compare` and a full local clone's `git log`). I classified all 169 non-merge commits below; the 43 merges are "sync main→next"/"resolve conflicts" plumbing with no independent diff worth tracking (their content is already covered by the leaf commits). This report supersedes the "81" estimate — treat 169 as the true corpus.

**Repo state check:** TS repo re-cloned fresh into scratchpad (the shared checkout at `../better-auth` was not touched, per worktree-isolation rules that blocked any `git -C`/`cd`/`GIT_DIR` command targeting it). Tags: `v1.6.25` = `07a646ea1` (2026-07-22), `v1.7.0-rc.2` = `cc708e51b` (2026-08-02). Diffstat: **968 files, +108,379/-39,452 lines** (the "327 files/+45.8k" figure noted in ACTIVE.md for a prior rc was stale — the range grew a lot by rc.2).

**Scope anchors used** (from `better-auth-py/AGENTS.md` + `docs/plans/ACTIVE.md`): server-side parity only; client/cli/expo/electron OUT; SAML/scim/stripe/open-api OUT; oidc-provider & mcp never ported (successor `oauth-provider` package WAS fully ported, W5-C, 4 phases). Port's adapters = SQLAlchemy + memory only (no drizzle/kysely/prisma/mongo). Port's `sso` plugin = OIDC only (no SAML files exist — confirmed via `ls plugins_ext/sso/`).

## 5. Items that would BREAK the port's current public API surface (plan deprecations early)

- **`DynamicBaseURL.trusted_proxy_headers` default mismatch.** The port's B10 wave (ACTIVE.md, shipped) defaults `trusted_proxy_headers=True`. TS 1.7 flips its equivalent (`advanced.trustedProxyHeaders`) to default **`false`** for dynamic-baseURL configs (breaking change #9 above) — a real security-posture divergence from the now-canonical TS default. The campaign needs to decide: flip the port's default (breaking for existing port users) or document the deliberate deviation.
- **`one_tap` plugin now requires `client_id` at init** (`ad35eadd`) — audit whether the port's `one_tap.py` currently allows a client-id-less config; if so, this becomes a required-field addition.
- **`captcha` plugin's `endpoints` matching semantics change** (wildcard support, `b36c38f9`) — port's `CaptchaOptions.endpoints` matcher needs review for whether it silently changes behavior for existing wildcard-shaped strings.
- **`generic_oauth` plugin's PKCE default flips `false`→`true`, and its callback route changes.** If the port's `generic_oauth.py` currently defaults `pkce=False` (matching pre-1.7 TS), this is a security-relevant default the campaign should flip deliberately, not silently inherit.
- **Rate-limit storage protocol**: TS's `BetterAuthRateLimitStorage` now *requires* `consume`; plain `get`/`set` storage is rejected at the type level. If the port exposes any pluggable rate-limit storage protocol (`rate_limit.py`), it should gain an atomic `consume`-style primitive to avoid a future breaking surprise.
- **Adapter contract**: TS adapters must implement `incrementOne` natively (no generic transaction fallback). If the port's adapter protocol (`adapters/base.py`) currently documents a *generic* guarded-update helper rather than a per-adapter native atomic primitive, that's the exact same contract gap TS just closed — worth closing proactively rather than reactively.
- **`captcha`/`oauth_provider` config surfaces grow**: DPoP support, protected DCR, extension surface (`clientDiscovery`), max_age enforcement, refresh-token-reuse-interval are all *new* `oauth_provider()` init kwargs in TS 1.7 — the port's `OAuthProvider` init signature will need matching additions when WP1 lands, not necessarily a break today, but worth flagging so the constructor isn't designed too narrowly in the interim.
